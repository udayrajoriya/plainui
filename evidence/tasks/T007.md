# T007 — Sanitizer and strict CSP feasibility

Completed 14 October 2026. Commit: recorded in Git history as the T007 commit.

The experiment bundles pinned DOMPurify only in its optional sanitizer script, with explicit RFC tag/attribute allowlists and DOM-fragment output. A separate private core HTML service parses developer component imports inertly under a cached `plainui-template` Trusted Types policy and rejects unsupported top-level nodes and executable template content; it does not import DOMPurify. The page uses external scripts only and enforces `script-src 'self'`, no unsafe-eval, and the `plainui-template`/`dompurify` policy names. It imports a native component definition and sanitizes an untrusted and an enhanced fragment on the same page. The enhanced result retains reviewed directives and an inert declaration template, while ordinary content loses directives. Scripts in a rejected import or sanitized fragment never execute. Security policy violations fail the test.

The measured release scaffold is 689 gzip bytes, the fragment-only sanitizer spike is 14,492 gzip bytes, and the combined measured script set is 16,379 gzip bytes using Node zlib gzip level 9 and mtime 0. That leaves 55,301 bytes under the 71,680-byte combined cap and does not trigger a numerical-budget revision. These numbers include dependency bytes but cannot establish final 1.0 size compliance; T094 measures the finished distribution.

Validation: `typecheck`, `check:boundaries`, and all three Playwright engines pass the `spike.csp-template`, `spike.csp-fragment`, `spike.no-script-execution`, and `spike.allowlist` test. [Detailed feasibility](../sanitizer-feasibility.md) and [size JSON](../size-baseline.json).

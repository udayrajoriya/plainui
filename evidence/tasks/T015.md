# T015 — Browser persistence

Completed 14 October 2026. Commit: recorded in Git history as the T015 commit.

`PersistenceBinding` validates an explicit storage kind/key and a single state or store cell, claims the namespaced key per origin, reads and validates `{version,value}` before reactive evaluation, and accepts only values with the declaration's top-level keys. Invalid or inaccessible storage leaves defaults in place with nonfatal diagnostics. Changed snapshots coalesce into one write in the scheduler's afterFlush phase. Disposal releases the claim; session reset does not touch the binding or storage, and there is no storage-event listener.

Validation: `typecheck`; 53 unit tests. New tests cover local/session selection, key encoding and collision, version mismatch, extra-key rejection, storage quota failure, coalesced writes, and restore after remount.

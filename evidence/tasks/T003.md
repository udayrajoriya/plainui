# T003 — Establish package boundaries and build entry points

Completed 14 October 2026. T002 is the dependency baseline; no new dependency pin or remote was added.

All C02 packages now have `src/index.ts`. Core contains private request, DOM, and action service interfaces and a versioned official module bridge. Forms imports only the data action-service interface. Runtime composition accepts injected services; its current implementations deliberately report that mounting and request/action behavior are scheduled for later tasks. Router, fragments, and UI provide a shared installer implementation for their classic and ESM entry adapters.

`scripts/check-boundaries.mjs` checks static and type imports against package rules and detects cycles. It permits optional modules to reach core only through `core/src/module-bridge.ts`, prohibits DOMPurify outside fragments, and prohibits dynamic import/require in package source. Unit probes deliberately insert illegal core/optional, private-core, forms/controller, DOMPurify, cycle, and dynamic-import edges and verify rejection. The current graph has 22 source files and no violation.

`scripts/build.mjs` produces minified ES2022 classic IIFE and ESM entries for `plainui`, router, fragments, and UI, plus `plainui.css`. Each has a source map. It emits declaration stubs as `.d.ts` for classic and `.d.mts` for direct ESM imports, with generated internal declarations under `dist/types`. The same source entries produce unminified `dist/dev` builds with a debug assertion enabled. Optional ESM entries contain a relative external `./plainui.mjs` import; optional classic entries register with the existing `window.PlainUI` bridge and report a clear error when core is absent. The [archived build manifest](../build/T003-build-manifest.json) records every bundled input.

`scripts/check-build.mjs` verifies all entry filenames, maps and declarations; proves that both main bundles include core/data/forms/components and optional bundles include no core/runtime source; checks the relative ESM bridge import; rejects eval/Function identifiers in browser artifacts; verifies debug code appears only in development output; and compiles a temporary TypeScript consumer of the direct `.mjs` files.

Windows validation with Node 24.21.0 and pnpm 12.10.1: `typecheck`, `check:boundaries`, and `build` passed; 9 unit tests passed; and 18 Playwright tests passed across Chromium, Firefox, and WebKit. Browser tests cover classic missing-core errors, classic registration, ESM installer identity, and the T002 toolchain smoke. `python scripts/spec_baseline.py --check` also passed. Linux was not rerun for T003 because the Ubuntu WSL distribution used for T002 is no longer installed and the Docker Linux daemon is unavailable in this session. T003's stated acceptance cases passed on Windows.

These are build scaffolds. T004 adds the directive schema, T017 implements mounting and runtime composition, and T077 fills out optional styles. No release behavior is claimed from the stubs.

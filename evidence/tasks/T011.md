# T011 — Scopes and extension registries

Completed 14 October 2026. Commit: recorded in Git history as the T011 commit.

Scopes now have independent lexical parent and owner links, per-root monotonic IDs, separate binding/ref/resource maps, duplicate declaration checks across state/derived/resource/action/alias names, reserved context names, and lexical shadowing. Component scope creation links directly to the app scope rather than a caller-local scope. Context cells are read-only; refs form a separate namespace and clean up idempotently. App-only resource resolution cannot reach local resources.

The extension registry validates names, rejects built-ins and duplicates across kinds, records adapter versions, and freezes registration at compilation start. Public context and adapter/behavior type contracts are staged in `public-api/types.ts`; T024 completes the full public API.

Validation: `typecheck`, `build`, 45 unit tests. Acceptance IDs `scope.shadow`, `scope.duplicate-cross-kind`, `scope.reserved`, `scope.ref-shadow`, `scope.app-only`, `registry.after-mount`, `registry.builtin`, and `scope.component-isolation` pass.
